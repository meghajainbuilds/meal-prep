# Meal planning: goals & requirements (template)

**Fill this in with your own goals, constraints, preferences, and planning context, then save as `.claude/requirements.md` (gitignored).** Every job that generates or refines a weekly menu loads this document as its system prompt, so the AI knows what rules to honor. Accurate requirements lead to accurate menus.

**How to update:** edit this file whenever your preferences change. Each new weekly menu generation reads the current version. Date the file so a future reader (or future-you) knows how fresh the guidance is.

## 1. Goals and scope

State the overall approach: who you are planning for, what cadence (one week at a time? a month?), and the broader goals.

- **Household**: how many people, ages/stages, who cooks, who does prep
- **Planning cadence**: generate one week first, improve after N weeks of use? Or something else?
- **Timezone and week-start**: when a "week" begins (Monday in Seattle? Sunday somewhere else?)
- **Personal goals (owner only)**: weight, energy, bloat, bowel comfort, specific health markers — only the eater's goals, not everyone's
- **Private planning context**: age, height, starting weight, exercise routine, breastfeeding/pregnancy, anything that shapes targets
- **Clinician / medical context**: anything a doctor or RD has said that should take priority
- **Measurement approach**: do you weigh food, use cups/spoons, use hand portions, read labels?
- **Pairings/plate-building rule**: does every day arrive already paired into complete meals, or do you compose plates each morning?

## 2. Food and meal rules

Hard rules the plan must honor. Allergies, dietary restrictions, cuisines, ingredients to always include or avoid.

- **Allergies and cross-contact**: list them explicitly (nut-free, sesame-free, dairy-free, etc.)
- **Vegetables**: raw vs cooked preference, specific favorites, specific aversions
- **Starches / grains**: which belong in rotation, which to avoid, portion rules
- **Proteins**: how many major sources per week, which get rotated, which get repeated
- **Fish, seafood, meat rules**: frequency, when in the day, no-reheat rules
- **Prep/cuisine style**: Indian / Japanese / Mediterranean / Mexican / etc., which comes first
- **Specific ingredient quirks**: things that must stay separate, things that must stay combined
- **Freeze / batch rules**: what freezes well, what doesn't, what gets made ahead

## 3. Daily rhythm

Meal times and what each slot looks like.

- **Meal time windows**: breakfast / mid-morning / lunch / dinner / evening — exact times
- **Breakfast style**: quick vs elaborate, specific recurring items (smoothie formula, bread + egg)
- **Standing daily items**: supplements, drinks, soaked seeds — anything that counts toward daily nutrition
- **Hunger patterns**: when the eater tends to get hungry; what fuels low-energy slots

## 4. Prep / cooking support

Who does the chopping and roasting? Session rhythm? Rules for batching?

- **Who preps**: house manager, owner, both
- **Sessions**: how many per week, which days
- **Batching rule**: by ingredient across the week? by recipe? by cooking method?
- **Mandatory activities**: roasting, chopping, make-ahead bases (e.g. tomato puree)
- **Picture style**: ingredient photos vs dish photos
- **Autonomy**: can the house manager execute from this view alone?
- **Instruction detail level**: cut styles in method? quantities as "1-inch cubes" or "chopped"?

## 5. Dashboard and ingredient requirements

How the plan surfaces to you day-of, what's shared vs private, what views matter.

- **Views**: Week, Day, Ingredients, Prep, Recipes — which are user-facing, which are internal
- **Finished-dish photos**: everywhere the dish is mentioned, except where?
- **Recipes library scope**: what counts as a recipe (actual recipes) vs plate component (plain rice, roti, yogurt, simple vegetables)
- **Ingredients view**: Fresh vs Pantry separation, Have/Buy checks, picture per item, "Used in" field naming recipes
- **Day view actions**: how to log what was actually eaten, how to swap or edit a planned meal, inline vs detached forms
- **Public read-only scope**: which parts are visible to a signed-in visitor, which stay owner-only (personal health details should always stay private)
- **Snapshot durability**: how long to keep past weeks browsable; what survives revisions

## 6. Weekly planning process

What should happen before each new week is generated?

- **Inventory check**: ask what's in the fridge/pantry; what to assume if no answer
- **Leftover carryover**: use delicate greens first, reuse only when fresh
- **Family batch quantities**: how to size against actual appetite and leftovers
- **Rotation rules**: how to vary from last week's menu, which items can repeat

## 7. Provisional guidance and open work

Nutrition targets (as working estimates, not prescriptions), rationale to document per menu, open questions.

- **Starting nutrition range** (as rough estimates, adjust with experience): calories/day, protein grams/day, fibre grams/day
- **What to count** (don't treat as free extras): oils, seeds, bread, smoothies, snacks
- **Menu rationale to document**: protein distribution, fibre sources, fluid, starch portions, fat for satiety
- **Source authority**: chef sources guide flavour; nutrition claims need credible health references
- **Open questions / things in progress**: anything the clinician is still assessing, products being researched
